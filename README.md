# Карманный музей

Школьный сайт по истории России XVIII–XIX веков. Монолит Django 5.2: серверные шаблоны, стандартная сессионная авторизация, Django Admin. Локально SQLite; конфигурация PostgreSQL и Docker для сервера включена.

Документы для защиты: [глава 1](docs/chapter-1.docx) и [презентация](docs/presentation.pptx). Описание файлов — в [docs/README.md](docs/README.md).

В комплекте: 3 эпохи, 9 тем, 36 карточек с текстами 80–150 слов, 36 локальных учебных иллюстраций, 9 минивикторин, 3 итоговых теста. Всего 24 вопроса, каждый с четырьмя ответами и пояснением. Исторические изображения и источники перечислены в [ATTRIBUTION.md](ATTRIBUTION.md) и на `/sources/`.

## Быстрый запуск на Windows

Нужен Python 3.12–3.14. Проверено с Python 3.14.

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

Скрипт создаёт `.venv`, устанавливает зависимости, применяет миграции, загружает материалы и создаёт два локальных аккаунта со случайными паролями. Откройте http://127.0.0.1:8000/. Учётные данные `student` и `museum_admin` сохраняются только в файле `.local-accounts.txt`, исключённом из Git и Docker. Повторный запуск не меняет существующие пароли и материалы. Для остановки нажмите Ctrl+C в окне сервера.

## Ручная установка

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
$env:DEBUG = 'True'
.\.venv\Scripts\python manage.py migrate
.\.venv\Scripts\python manage.py seed_demo
.\.venv\Scripts\python manage.py createsuperuser
.\.venv\Scripts\python manage.py runserver 127.0.0.1:8000
```

Linux/macOS:

```sh
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
export DEBUG=True
python manage.py migrate
python manage.py seed_demo
python manage.py createsuperuser
python manage.py runserver 127.0.0.1:8000
```

Не нужно пересобирать иллюстрации: PNG включены в `demo_assets/`. При желании их можно пересоздать командой `python tools/build_demo_assets.py`. Шрифты берутся из ОС; сайт использует системные шрифты, внешние CDN не нужны.

## Учебный маршрут и правила

Гость читает опубликованные материалы. Для отметок и тестов нужны регистрация или вход. Email и школьные данные не запрашиваются.

Откройте эпоху → тему → четыре карточки. Кнопка «Читать полный текст» раскрывает материал без обязательной анимации. Отметку изучения можно снять; она влияет только на процент чтения. Итоговый тест доступен сразу, без блокировки по чтению.

Минивикторина: один вопрос, 5 баллов за правильный ответ. Итоговый тест: пять вопросов, 10 баллов за каждый. Общий счёт — сумма лучших результатов доступных опубликованных тестов. Максимум начального набора — 195. Попытки 20, 40, 30 дают вклад 40. После снятия теста с публикации история сохраняется, а вклад исключается. Скрытие родительской эпохи или темы также исключает соответствующие недоступные тесты из текущего счёта.

Вопросы проверяются на сервере. Пояснения и признаки верных ответов не выводятся до отправки. Требуются ответы на все вопросы. Отправка атомарна; в PostgreSQL строка попытки блокируется `select_for_update()`. Повторная отправка возвращает прежний результат. SQLite подходит для локального показа; проверка конкурентных запросов в развёрнутой среде требует PostgreSQL.

## Управление материалами

Вход в `/admin/` доступен только пользователям с `is_staff`. Для полного управления создайте суперпользователя.

1. Создайте эпоху и тему как черновики.
2. Добавьте четыре карточки: событие, человек, предмет, интересный факт. Заполните анонс, текст, период и ссылку. У изображения нужны подпись и alt. Допустимы JPEG, PNG, WebP до 5 МБ; содержимое проверяется сервером. Изображение можно не загружать — появится заглушка.
3. Создайте минивикторину в черновике. Добавьте вопрос через раздел «Вопросы»; варианты вводятся на той же странице. Требуются четыре варианта, ровно один правильный и непустое пояснение.
4. В списке тестов выберите действие «Опубликовать выбранные материалы». Неполный тест не опубликуется, админка покажет причину.
5. Опубликуйте четыре карточки, затем тему. Для темы проверяются ровно четыре опубликованные карточки разных типов и опубликованная минивикторина.
6. Создайте итоговый тест эпохи с пятью вопросами по разным темам. Опубликуйте его и эпоху.

Вопросы и варианты опубликованного теста не редактируются. Чтобы изменить тест без попыток, снимите его с публикации; для минивикторины сначала снимите тему. Если есть хотя бы одна попытка, создайте новую версию действием в списке тестов. Копия появится в черновике со всеми вопросами. Для смены версии минивикторины: снимите тему, затем старый тест, опубликуйте исправленную копию и верните тему. Для итогового теста достаточно снять старую версию и опубликовать новую. База не допускает одновременно две опубликованные минивикторины темы или два итоговых теста эпохи.

История в админке доступна только для чтения. Удаление контента из админки отключено: используйте снятие с публикации. Исторические связи дополнительно защищены `PROTECT`.

`seed_demo` создаёт только отсутствующие элементы стартового набора, не перезаписывает правки администратора, не восстанавливает намеренно снятую публикацию и не удаляет результаты. При использовании имён/slug стартового набора для собственного контента сначала создайте резервную копию. Для чистого демонстрационного набора запускайте команду на новой базе.

## Проверки

```powershell
$env:DEBUG = 'True'
.\.venv\Scripts\python manage.py check
.\.venv\Scripts\python manage.py test
```

Автоматические тесты проверяют наполнение, регистрацию, совместные фильтры и поиск по кириллице, отметки, подсчёт лучших баллов, максимум 195, повторную отправку, подмену вариантов и чужой попытки, скрытие черновиков и родителей, публикацию, неизменность версий с историей, CSRF, проверку изображений и повторный seed.

Для браузерной проверки на локальном экземпляре можно установить `pip install -r requirements-dev.txt`, выполнить `python -m playwright install chromium` и `python tools/browser_check.py`. Скрипт использует локальные демо-доступы без вывода паролей, проходит маршрут ученика и проверяет ширину 360 px. Скриншоты сохраняются в `test-results/`.

## Развёртывание с PostgreSQL и HTTPS

Внешний сервер и домен в комплекте не предоставляются. Приложение готово для размещения на обычном Python/VPS-хостинге. Нужны Docker Compose, домен и доверенный HTTPS reverse proxy, например Caddy. Приведённые команды выполняются в Linux shell на сервере.

1. Скопируйте `.env.example` в `.env`. Укажите случайный `SECRET_KEY` (например, `python -c "import secrets; print(secrets.token_urlsafe(64))"`), пароль PostgreSQL, домен в `ALLOWED_HOSTS` и полный HTTPS origin в `CSRF_TRUSTED_ORIGINS`. Оставьте `POSTGRES_HOST=db`.
2. Соберите и подготовьте приложение:

```sh
docker compose build web
docker compose up -d db
docker compose run --rm web python manage.py migrate
docker compose run --rm web python manage.py seed_demo
docker compose run --rm web python manage.py collectstatic --noinput
docker compose run --rm web python manage.py createsuperuser
docker compose run --rm web python manage.py check --deploy
docker compose up -d
```

3. Настройте HTTPS proxy домена на `127.0.0.1:8080`. Например, в Caddyfile:

```text
museum.example.org {
    reverse_proxy 127.0.0.1:8080
}
```

Nginx слушает только loopback хоста и сообщает Django, что внешний запрос пришёл по HTTPS. Не открывайте этот listener напрямую в интернет. Waitress не публикуется на хост. `SECURE_PROXY_SSL_HEADER` допустим только при таком доверенном прокси, который перезаписывает заголовок. Django перенаправляет HTTP на HTTPS, использует secure cookies и HSTS. `DEBUG=False`; локальный секрет запрещён в production.

Nginx отдаёт `/static/` и `/media/` из отдельных общих Docker volumes; данные PostgreSQL — в своём volume. При ручной установке запустите `collectstatic` и настройте web-сервер на `staticfiles/` и `media/`. Запускайте приложение через `waitress-serve --listen=127.0.0.1:8000 config.wsgi:application` за HTTPS proxy. `runserver` предназначен только для разработки. `.env` автоматически читает Docker Compose; при ручном запуске экспортируйте переменные в окружение процесса.

## Копирование и восстановление

Перед обновлением остановите запись и сохраните базу вместе с media. Не удаляйте volumes командой `down -v`.

Для локального SQLite остановите сервер и выполните в PowerShell:

```powershell
$backupDir = Join-Path 'backups' (Get-Date -Format 'yyyyMMdd-HHmmss')
New-Item -ItemType Directory -Path $backupDir -Force
Copy-Item -LiteralPath 'db.sqlite3' -Destination $backupDir
Copy-Item -LiteralPath 'media' -Destination $backupDir -Recurse
```

Восстановление: остановите сервер; сохраните текущие файлы отдельно; скопируйте `db.sqlite3` из выбранной копии в корень проекта, восстановите соответствующую папку `media` из той же копии. Запустите `migrate`, `check` и сервер. Для полного восстановления `media` используйте пустую целевую папку, чтобы не смешивать наборы файлов.

Для Docker на Linux (копия сохраняется на хосте):

```sh
mkdir -p backups
docker compose stop web
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > backups/database.dump
docker compose run --rm --no-deps -v "$PWD/backups:/backup" web tar -czf /backup/media.tar.gz -C /app media
docker compose start web
```

Проверьте успешные коды команд и непустые архивы; перенесите копии и `.env` в защищённое внешнее хранилище. Для восстановления в совместимую среду:

```sh
docker compose stop web
docker compose exec -T db sh -c 'pg_restore --clean --if-exists --no-owner -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < backups/database.dump
docker compose run --rm --no-deps -v "$PWD/backups:/backup:ro" web tar -xzf /backup/media.tar.gz -C /app
docker compose run --rm web python manage.py migrate
docker compose run --rm web python manage.py collectstatic --noinput
docker compose start web
```

Восстанавливайте media в пустой volume или на новый сервер, чтобы исключить старые лишние файлы. Перед восстановлением сделайте отдельную копию текущего состояния. Обновляйте код и запускайте миграции только после проверенной резервной копии. Для отката приложения используйте совместимые код и базу из одного релиза.
